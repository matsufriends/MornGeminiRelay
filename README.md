# MornGeminiRelay

Gemini (gemini.google.com) に投げた質問と回答を Slack のスレッドへ転送し、質問履歴を Markdown でダウンロードする Chrome 拡張。

## インストール

1. `chrome://extensions` → デベロッパーモード ON → 「パッケージ化されていない拡張機能を読み込む」でこのディレクトリを選ぶ
2. Slack に転送する場合は Slack App を作り、以下を設定する
   - Bot Token Scopes に `chat:write`、`files:write`、`chat:write.customize` を追加してワークスペースにインストールし、Bot User OAuth Token (`xoxb-…`) を控える。既存の App に権限を追加した場合も再インストールが必要
   - 投稿先チャンネルで `/invite @<App 名>` を実行する (招待せずに公開チャンネルへ投稿するなら `chat:write.public` も追加)
   - チャンネル詳細の最下部にあるチャンネル ID (`C…`) を控える
3. 拡張機能に Bot Token とチャンネル ID を入力し、「保存」を押す。Slack での自分の投稿者名を変えたい場合は「Slack での表示名」も入力する (空欄ならメールを除いた Google アカウント名。取得できなければ「ユーザー」)

## 質問履歴を保存

どのページからでも「Gemini を開いて履歴を保存」を押すと、保存専用の Gemini タブを開き、会話一覧の取得から `.md` のダウンロードまで順に実行する。Gemini にログイン済みであることが必要。複数アカウントを使っている場合は、新しく開いた Gemini のアカウントが対象になる。

- 会話一覧を末尾までスクロールし、追加で読み込まれる会話も取得する。
- 各会話を開き、質問の描画と上方向への追加読み込みが落ち着いたら保存する。固定の 5 回スクロール待ちは行わない。
- `ダウンロード/gemini-history-<日付>/<会話タイトル>.md` に 1 会話 1 ファイルで出力する。対象は自分の質問のみで、Gemini の回答や送信日時は含まない。同じ質問を複数回送っていた場合も、そのまま残す。
- 完了まで保存専用タブを操作しない。タブを閉じると中止する。進捗や停止理由は拡張機能を開くと確認できる。
- ダウンロード成功を確認してから次の会話に進む。本文が取得できない場合や保存に失敗した場合は、黙って飛ばさず停止する。

Gemini の画面に読み込める会話が対象。DOM の更新停止を 800ms 待って進むため、Gemini 側の表示変更や、読み込み中表示を伴わない遅い応答では完全性を保証できない。取得速度も Gemini の読み込み時間に依存する。

## チャットを Slack に送る

過去のチャットを、リアルタイム転送と同じ形式 (質問 → 回答 → コード・Canvas の添付) で Slack に送れる。

1. 拡張機能の「全チャットを取得」を押す。専用の Gemini タブで会話一覧を末尾まで読み込み、終わるとタブを閉じる
2. プルダウンでチャットを選び、右の「送信」を押す。専用タブでそのチャットを開き、最初の質問を親にした新しいスレッドへ順に投稿して、終わるとタブを閉じる

- すでにスレッドがあるチャットも新しいスレッドに送り、以降のリアルタイム転送も新しいスレッドに入る。
- 投稿の完了を待たずに次のやり取りを読み進める。本文同士・添付同士の順序はそれぞれ保ち、添付の完了待ちで後続の本文を遅らせない。Slack から投稿が速すぎると返されたら (429)、指定された秒数だけ待って送り直す。完了まで専用タブを操作しない。
- 画像の添付はファイル名が画面に残らないため `画像` と表示する。Canvas はプレビューが 15 秒以内に読み込まれなければ添付しない。
- 会話一覧 (URL とタイトル) はブラウザを閉じるまでメモリ上に置く。

## Slack 転送とデータ保存

投稿者名とアイコンは、ユーザーが「設定した表示名」＋ 👤 (`:bust_in_silhouette:`)、Gemini が「Gemini」＋ 🤖 (`:robot_face:`)。遅れて届くユーザーの添付名の追記もユーザーの名前と 👤 にする。コード・Canvas のファイル共有メッセージは「Gemini 添付」＋ 📎 (`:paperclip:`) にする。本文内には投稿者名の見出しを追加しない。投稿者名・アイコンの変更には `chat:write.customize` の許可が必要。

Canvas の「エラーを修正」ボタンから生成された回答も、本文と修正後の HTML を同じスレッドへ転送する。この操作で Gemini が内部的に追加する空の質問は投稿しない。過去チャットの送信でも同じ扱いにする。

送信操作後、新しい質問が Gemini に描画されるか、現在の入力欄が空になったら、質問を Slack へ転送する。受理を 150ms ごとに確認し、受理できたら質問本文の描画や回答の生成を待たずに転送を開始する。添付名の表示が遅れている場合は、本文を先に送り、添付名を後から同じスレッドへ追記する。受理の確認は最大 15 秒待ち、確認できなければコンソールへ理由を出す。入力欄の作り直しや、質問数が増えない描画にも対応する。質問にファイルやフォルダが添付されていれば、その名前を `📎 添付: …` として末尾に付ける (中身は送らない)。ファイル名は添付ボタンのラベルから完全な形で取る。画像は送信後の表示に名前が残らないため、選択・ドロップ・貼り付けの時点でファイル名を控えて添付順に当てる (貼り付けた画像はブラウザが付けた `image.png` などになる)。新しい会話の最初の質問が親投稿になり、その会話の Gemini の回答と以降の質問はすべて親投稿のスレッドに返信する。回答は停止ボタンが消え、Gemini の回答完了表示が出た時点で転送する (100ms ごとに確認)。完了表示がない場合は本文が 1.5 秒変わらなくなった時点で転送する。質問の Slack 投稿と回答の完了検知は並行して進める。本文とファイル添付は別々に順番待ちするため、大きな添付の転送中でも次の質問・回答本文を送信できる。見出し・太字・番号付き/入れ子の箇条書き・インラインコードは Slack の書式に変換し、回答中のコードブロックは本文から外して `📎 code-<n>.<拡張子>` の目印を残し、同じスレッドにファイルとして添付する (`files:write` が必要)。Canvas のコードは本文の完了後も生成が続くため、本文の投稿後も最大 10 分、会話内のプレビューを見張る。過去の回答にある Canvas も対象とし、取得した HTML が 1.5 秒変わらず、前回添付した内容と異なる場合に `canvas-<n>.html` を同じスレッドへ再添付する。同じページを開いている間は送信済みの内容をメモリ上に保持して重複添付を防ぐ。次の質問・自動修正では監視を引き継ぎ、会話を移動すると停止する。ページを読み直すと比較用の記録は消える。Gemini が修正済みと回答しても実際の HTML が変わらなければ再添付しない。問い合わせは Gemini のページ側で動く `canvas-bridge.js` が送り (拡張機能側から直接送ると応答が返らなかったため)、HTML はプレビューのフレームで動く `preview.js` が返す。プレビューは読み込み役のページが HTML を Blob にして同じフレームを blob: URL へ遷移させ、遷移後は blob: URL を読み直せないため、Blob が作られた瞬間に中身を sessionStorage に控えて遷移後に取り出す。控えがなければ表示中の DOM で代用する (スクリプトによる書き換えを含む)。コードタブのエディタは見えている行しか描画しないので使わない。Gemini が HTML に差し込む `<script data-bard-client-injected>` (認証トークン・Firebase 設定入り) は取り除き、それでもトークンやキーの値が残っていれば送らない。履歴の一括保存では Slack に送信しない。

Incoming Webhook は投稿の `ts` を返さず親投稿のスレッドに返信できないため、Bot Token で `chat.postMessage` を使う。

拡張機能は質問本文を蓄積しない。永続保存するのは Bot Token・チャンネル ID・表示名と、会話 ID → 親投稿 `ts` の対応表のみ。作業中の会話 URL・タイトルと進捗だけを `chrome.storage.session` のメモリ上に保持し、本文は `.md` に直接出力する。タブを閉じると作業情報も削除する。旧版で保持していた質問履歴・取り込み情報・Discord Webhook URL は、更新後に拡張機能が起動すると削除する。
